# 项目架构

本文描述 `local-chain` 的组件划分、网络与数据流、Docker 编排与启动链路。日常使用见根目录 [README.md](../README.md)。

---

## 1. 目标与边界

- **目标**：在一台机器上拉起可出块的 Parlia 测试链，提供 RPC 与 Blockscout，并支持通过 Tailscale 从外出设备访问。
- **边界**：非生产主网；验证者进程内解锁私钥；默认放开 CORS / `http.vhosts` 以便家庭网访问。

| 链参数 | 值 |
| --- | --- |
| `chainId` / `NetworkId` | `100000` |
| 共识 | Parlia（`period=3`，`epoch=200`） |
| Gas Price | `20 Gwei` |
| `STATE_SCHEME` | `hash` |
| 节点镜像 | `.env` 中 `CHAIN_IMAGE` |

## 2. 逻辑拓扑

```text
                         ┌─────────────────────────────────────┐
                         │           客户端（本机/外出）          │
                         │  浏览器 / MetaMask / curl / 业务 DApp │
                         └───────────────┬─────────────────────┘
                                         │ Tailscale / 局域网
                    ┌────────────────────┼────────────────────┐
                    │                    │                    │
                    ▼                    ▼                    ▼
              :80 Blockscout      :8575 archive        :8565 full
                    │                    │                    │
                    │              local-chain_net             │
                    │                    │                    │
                    │         ┌──────────┴──────────┐         │
                    │         │                     │         │
                    │    archive_node          full_node      │
                    │         │                     │         │
                    │         └──────────┬──────────┘         │
                    │                    │ P2P                │
                    │         ┌──────────┴──────────┐         │
                    │         ▼                     ▼         │
                    │  validator_1 ◄─────────► validator_2    │
                    │   (出块/投票)              (出块/投票)    │
                    └─────────────────────────────────────────┘
```

**推荐对外暴露**

| 流量 | 目标 | 原因 |
| --- | --- | --- |
| 业务 / 钱包 RPC | `archive` 或 `full` | 不持解锁验证者密钥 |
| 历史状态 / 浏览器索引 | `archive`（含 `debug,trace`） | Blockscout 与溯源需要 |
| 验证者 RPC | 尽量仅内网 | 内存中解锁私钥 |

## 3. 仓库结构与职责

```text
local-chain/
├── docker-compose.yaml      # 四节点编排（无 YAML 锚点）
├── start.sh / stop.sh       # 一键启停（含 Blockscout）
├── reset_*.sh               # 按角色清库
├── .env / .env.example      # 镜像、密码、PUBLIC_HOST、gas 等
├── scripts/reset_lib.sh     # reset 公共逻辑
├── rpc_test.sh              # full + archive RPC 健康检查
├── docs/                    # 本架构文档等
├── blockscout/              # 独立 compose 项目（加入 local-chain_net）
├── node_validator_1|2/      # 验证者配置与脚本
├── node_full/               # 全节点
└── node_archive/            # 归档节点
```

### 3.1 单节点目录

| 路径 | 职责 |
| --- | --- |
| `config-src/genesis.json` | 创世；四节点必须一致 |
| `config-src/config.toml` | NetworkId、矿工/交易池 gas、P2P 等 |
| `app/node` | geth datadir（compose 挂载为 `/data/app/node`） |
| `app/keys` | 验证者密钥（BLS / keystore / nodekey） |
| `node_*_start.sh` | 容器入口脚本（挂载覆盖镜像内同名脚本） |

### 3.2 角色与主脚本

| 角色 | 目录 | 入口脚本 | 行为摘要 |
| --- | --- | --- | --- |
| 验证者 | `node_validator_*` | `node_validator_start.sh` | 生成/复用密钥 → init → 注册 StakeHub → `--mine --vote` |
| 全节点 | `node_full` | `node_full_start.sh` | init → 同步 → RPC（`gcmode=full`） |
| 归档 | `node_archive` | `node_archive_start.sh` | init → 同步 → RPC（`gcmode=archive` + debug） |

验证者脚本读取 `${BASE_DIR}/config/{genesis,config}`；compose 将 `config-src` 同时挂到 `/data/chain/config` 与 `/data/chain/config-src`。  
full / archive 读取 `${BASE_DIR}/config-src/`。

## 4. Docker 编排

### 4.1 项目与网络

| 项目 | Compose 文件 | 网络 |
| --- | --- | --- |
| `local-chain` | 根目录 `docker-compose.yaml` | 创建 `local-chain_net` |
| `local-chain-blockscout` | `blockscout/docker-compose.yml` | `default` + **external** `local-chain_net` |

Blockscout 的 `backend` 双网卡：业务网访问 DB/Redis，`chain_net` 访问 `http://archive_node:8545/`。

### 4.2 容器与端口（宿主机）

| 服务 | 容器名 | HTTP | WS | P2P |
| --- | --- | --- | --- | --- |
| validator_1 | `validator_1` | 8545 | 8546 | 30303 |
| validator_2 | `validator_2` | 8555 | 8556 | 30304 |
| full_node | `full_node` | 8565 | 8566 | 30305 |
| archive_node | `archive_node` | 8575 | 8576 | 30306 |
| Blockscout proxy | `proxy` | 80 | — | — |
| stats / visualizer（经 proxy） | — | 8080 / 8081 | — | — |

容器内节点 HTTP/WS 统一为 `8545`/`8546`，P2P 为 `30303`；由宿主机端口映射区分。  
`BIND_ADDR` 默认 `0.0.0.0`，供局域网 / Tailscale 接入。

### 4.3 卷挂载模式（以验证者为例）

| 宿主机 | 容器内 | 说明 |
| --- | --- | --- |
| `node_*/app` | `/data/app` | 数据与密钥持久化 |
| `config-src` | `/data/chain/config` (+ `config-src`) | 创世与 toml |
| `node_*_start.sh` 等 | `/data/chain/bin/scripts/...` 或 `/data/chain/...` | 覆盖镜像脚本 |
| （镜像自带） | `/data/chain/bin/{geth,bootnode,...}` | 二进制不挂载覆盖 |

## 5. 启动与数据流

### 5.1 `start.sh` 流程

```text
start.sh
  ├─ source .env
  ├─ stop.sh --keep-network          # 默认先停（保留网络）
  ├─ compose up validator_1
  ├─ 等待 nodekey → 解析公钥
  ├─ 写入 BOOTNODES=enode://<pk>@validator_1:30303
  ├─ compose up validator_2 full_node archive_node
  ├─ 等待 archive RPC（:8575）
  ├─ 同步 PUBLIC_HOST → blockscout/.env（NEXT_PUBLIC_*）
  └─ blockscout: compose up -d
```

`BOOTNODES` 使用 **Docker DNS 名** `validator_1` 与容器内 P2P 端口 `30303`，不是宿主机映射端口。

### 5.2 验证者首次生命周期

```text
无 keys? ──是──► node_generate_key.sh
              │     ├─ BLS
              │     ├─ validator keystore
              │     └─ nodekey / enode.txt
              ▼
         geth init（写 init.log → 解析 RIALTO_HASH）
              ▼
         后台 geth（001 可挖矿；非 001 先不同步挖矿）
              ▼
         轮询余额 ≥ 2005 → create-validator
              ▼
         标记 stake_registered → exec 前台挖矿
```

### 5.3 Blockscout 数据流

```text
浏览器 ──HTTP──► proxy:80 ──┬── /api* ──► backend:4000
                            └── /     ──► frontend:3000

backend ──JSON-RPC──► archive_node:8545   (local-chain_net)
backend ──SQL───────► postgres (blockscout db)
frontend NEXT_PUBLIC_* 指向 PUBLIC_HOST（客户端可达地址）
```

注意两套地址：

| 场景 | 地址 |
| --- | --- |
| 容器内索引 | `http://archive_node:8545/` |
| 浏览器 / 钱包 | `http://<PUBLIC_HOST>:8575` 等 |

## 6. 配置分层

```text
.env（根）
  ├─ compose 注入节点环境（PASSWORD、GAS、BOOTNODES、BIND_ADDR…）
  └─ start.sh 同步 PUBLIC_HOST → blockscout/.env

节点 config-src/
  ├─ genesis.json   # 链身份、系统合约、alloc
  └─ config.toml    # NetworkId、GasPrice/PriceLimit、P2P BootstrapNodes=[]

启动脚本默认值
  └─ 可被 compose environment 覆盖（如 GC_MODE、HTTP_API、CACHE_MB）
```

与 gas 相关的一致性：

- `.env` → `MINER_GAS_PRICE=20000000000`（20 Gwei）
- `config.toml` → `GasPrice` / `PriceLimit` 同为 `20000000000`
- 验证者脚本 `--miner.gasprice` 使用环境变量

## 7. 重置与状态

| 脚本 | 默认清理 | 可选 |
| --- | --- | --- |
| `reset.sh` | down 全部 → 清四节点 `app/node` + Blockscout 数据目录 → `start.sh` | `--wipe-keys` / `--no-start` |
| `start_blockscout.sh` / `stop_blockscout.sh` | 仅启停浏览器 | — |
| `reset_blockscout.sh` | down 浏览器 → 清 Blockscout 数据目录 → `start_blockscout.sh` | `--no-start` |
| `reset_archive.sh` | `node_archive/app/node`（或根 `app/node`） | 停 `archive_node` |
| `reset_full.sh` | `node_full/app/node` | 停 `full_node` |
| `reset_validator.sh` | 两个验证者 `app/node` | `--wipe-keys` 清 `app/keys` |

安全约束（`scripts/reset_lib.sh`）：

- 拒删 `/`、`$HOME`、仓库根
- 默认仅允许仓库内路径；仓库外需 `FORCE_OUTSIDE_REPO=1`

改 `chainId` 后：清各节点数据（及按需密钥）+ Blockscout `docker compose down -v`。

## 8. 外部访问模型（Tailscale）

```text
外出笔记本 ──Tailscale──► 家中部署机:PUBLIC_HOST
                              ├─ :80   Blockscout UI/API
                              ├─ :8575 archive RPC
                              └─ :8565 full RPC
```

实现要点：

1. 宿主机端口绑 `0.0.0.0`
2. geth `--http.vhosts=*` / `--http.corsdomain=*`（可用 env 收紧）
3. Blockscout `NEXT_PUBLIC_API_HOST` / `APP_HOST` / `NETWORK_RPC_URL` = `PUBLIC_HOST`
4. `CHECK_ORIGIN=false`，避免 Host 校验挡住 MagicDNS

## 9. 依赖与运行时

| 依赖 | 用途 |
| --- | --- |
| Docker / Compose v2 | 编排 |
| 节点镜像内 `geth` / `bootnode` / `create-validator` | 链与注册 |
| GHCR Blockscout 镜像 | 浏览器栈 |
| （可选）Tailscale | 外出访问 |

宿主机无需单独安装 geth；脚本与配置由仓库挂载进容器。

---

## 10. 扩展建议

- 增加验证者：复制 `node_validator_*` 目录与 compose 服务，分配新端口与 `VALIDATOR_INDEX`
- 仅内网 RPC：将 `BIND_ADDR` 改为 Tailscale IP 或本机局域网 IP，避免误绑所有网卡
- 生产加固：关闭验证者对外端口、收紧 vhosts/CORS、Blockscout 前置 HTTPS 反代
